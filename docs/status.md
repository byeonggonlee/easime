## 개발 단계

1. **ime-core + 한글 엔진**: 완료
2. **CLI 데모**: 완료
3. **Wayland 입력기 프런트엔드(KDE)**: 완료. 실제 KDE에서는 한·영 입력만 확인
4. **상태 표시(트레이 아이콘 + 커서 옆 박스)**: 완료. 실제 Plasma 트레이는 미확인
5. **설정 GUI(Kirigami) + KDE 통합**: 전문가용 완료(활성화 카드, 즉시 반영). 자동 실행과 초보자용은 없음
6. **Linux 패키징**: 완료(`.deb`/`.rpm`, 배포판당 하나). 릴리스 태그는 사용자 결정
7. **XIM 프런트엔드(XWayland: 게임, Wine, Steam, 일부 IDE)**: 미착수
8. **일본어 1단계(로마자 → 가나)**: 완료
9. **후보창 → 일본어 2단계(Mozc 사전)**: 후보창과 단어 단위 변환 완료. 학습·문절 변환은 미착수
10. **GNOME(IBus 호환 D-Bus 서비스)**: 미착수, 조사 필요
11. **Windows(TSF, WinUI 3 설정 앱, 설치 프로그램)**: 완료. 실제 PC에서 W1–W14 문제 없음 보고(2026-11-09). 2026-11-10~11 회사 PC 피드백을 반영했고 W19·W20·W22(Excel)·W23(회사 메신저)은 문제 없음, W21은 옵션 단추 없음으로 보고되었다. 남은 것은 Excel의 일본어 입력(2026-11-12 실패 보고). W15·W17은 시험하지 않는다(형님 결정)
12. **중국어(병음, 간체·번체)**: 미착수
13. **macOS(InputMethodKit, SwiftUI, pkg)**: 미착수

## 알려진 한계

- **실제 환경 미검증**: Linux는 한자·일본어·트레이·설정 창·패키지 설치. Windows는 W1–W14(입력 시험)와 W16(설정 앱)이 문제 없다고 보고되었으나(상세 미기록) 런타임 없는 PC의 `setup.exe`, 제거·업그레이드의 세부(재시작 뒤), 후보를 직접 그리는 게임은 미시험이다. CI의 초록은 이를 대신하지 않는다.
- 일본어 변환은 **단어 단위**다. 문절·문맥 변환이나 학습이 있는 것처럼 소개하지 않는다.
- 상태 박스와 후보창은 고정 다크 테마이고 시스템 글꼴 크기·혼합 배율을 따르지 않는다. 2026-11-12에 선언한 시각 스타일([DESIGN.md 6절](../DESIGN.md))은 아직 구현하지 않았다. 한도를 넘는 긴 후보의 전체 내용을 확인하는 방법이 없다.
- 한글 자판은 활성 키보드 레이아웃의 keysym을 따른다(Linux). 레이아웃이 US가 아니면 어긋날 수 있다.
- XWayland 앱에서는 입력할 수 없다(XIM 없음).
- Windows **Excel**: 자모가 낱개로 들어가던 문제는 고쳤고 정상으로 보고되었다([W22](testing/windows.md), 고친 내용은 [구현](implementation/windows.md)). Excel이 셀마다 한/영을 정하는 기능(데이터 유효성의 IME 모드)은 따르지 않는다. **Excel의 일본어는 아직 안 된다**: `nihon`이 `nいhおn`처럼 들어간다(2026-11-12 보고, 원인 모름, [W22](testing/windows.md)).
- Windows: 모드는 응용 프로그램마다 따로이다(작업 표시줄 단추는 입력 중인 프로그램의 모드를 보인다). 후보를 직접 그리는 앱에서 마우스로 고를 수 없다. 32비트 프로그램용 DLL도 함께 설치한다(2026-11-11, 회사 메신저에서 입력된다고 보고: [W23](testing/windows.md)). 설치 파일에 코드 서명이 없고, 실제 PC 시험 전이라 릴리스에 올리지 않고 CI 아티팩트로만 둔다.
- 한국어 외의 설정 앱 번역(일본어, 번체, 간체, 영어)은 원어민 검토 전 초안이다.

## 이어서 할 일 (후보, 승인된 일정이 아님)

1. **실제 PC·데스크톱 시험**: 형님이 직접 해야 한다. Windows는 W1–W14, W16, W18의 Ignore 경로, W18, W19, W20, W22(한국어), W23을 마쳤고(문제 없음 보고) Excel의 일본어가 실패로 남았다. [W15, W17](testing/windows.md)은 시험하지 않고 버그 보고로 받기로 했다(2026-11-12 형님 결정). KDE 시험은 보류 중이다(2026-11-12). KDE는 [K1–T5와 새 K8(언어 전환 방식)](testing/kde.md) 전부 남았다(회사 Linux는 X11이라 시험할 수 없다: easime의 KDE 입력기는 Wayland 세션에서만 동작한다). 결과에서 입력 손실·중복이 나오면 회귀 시험으로 남긴다.
2. 상시 모드 확인 경로: Windows 작업 표시줄 단추는 확인되었다(W19). KDE 트레이의 실제 Plasma 확인이 남았다.
3. 후보창: Windows 후보 마우스 선택(`ITfCandidateListUIElementBehavior`), 시스템 색·글꼴·배율 연동, 긴 후보의 전체 확인.
4. XIM 프런트엔드(XWayland 앱).
5. 클립보드 기록(`Super+V`)과 이모지 선택기(`Super+.`): [concept.md](concept.md), [decisions.md](decisions.md).
6. 일본어 문절 변환·학습, 중국어, GNOME, macOS의 순서는 사용자의 우선순위와 1번의 결과로 정한다.

## 정리할 것

- 형님의 로컬 브랜치 `settings-gui-kde`(Kirigami 설정 앱 중간본)와 `candidate-window`(후보창 중간본)는 2026-11-07 토큰 소진으로 멈춘 작업이다. 같은 기능이 이미 `main`에 구현되어 있어(`settings/kde`, `frontend-wayland/src/candidate.rs`) **합치지 않는다.** 필요한 부분(화면 구성, 스크린샷)이 있으면 비교해서 가져오고, 브랜치를 지울지는 사용자가 정한다.
- **릴리스(v0.1.0) 뒤에 문서 정리**(2026-11-10 사용자 결정): 같은 사실이 여러 문서에 풀어 쓰여 있고(작업 표시줄 단추는 5개 문서, W19 상태는 4개 문서) 표 한 칸이 문단이 되어 있다. 새 규칙([AGENTS.md](../AGENTS.md) "One fact, one home")에 맞춰 `implementation/windows.md`, `testing/windows.md`, `platforms.md`, `DESIGN.md`부터 줄인다. 릴리스 전에는 고치는 문서에만 새 규칙을 적용한다.
