# easime 목표와 결정 사항

제품 컨셉과 대상 사용자는 [concept.md](concept.md)에 있다. 이 문서는 목표, 확정한 결정, 라이선스 메모다.
결정의 경위와 실험 결과는 [records/](README.md#특정-시점의-기록)에 두고, 여기에는 결정과 이유, 지금의 구현 상태만 적는다.
구현 상태는 코드가 있다는 뜻이다. 실제 환경에서 확인했는지는 [status.md](status.md)를 본다.

## 목표
기존 입력기(ibus-hangul, fcitx5, nimf, mozc, MS IME 등)에 의존하지 않고 **Rust로 직접 만든 입력기**로 입력한다.
- 언어: 1차 **한국어**(두벌식) → 단기 **일본어**(로마자→가나, 그다음 Mozc 참고 한자 변환) → 장기 **중국어**(병음, 간체/번체)
- 플랫폼: **Linux(KDE Plasma 6 Wayland 최우선 → GNOME)** → **Windows** → macOS
- 앱: 가능한 한 **모든 앱** (Wayland 네이티브, Electron/IDE, XWayland, 게임/Wine)
- 배포: Linux는 **GitHub Releases에 .deb/.rpm**, Windows/macOS는 각 OS의 설치 패키지

## 결정 사항

구현 열: **완료**(코드가 `main`에 있다), **일부**, **예정**(결정만 했다).

### 제품·입력

| 항목 | 결정 | 구현 |
|---|---|---|
| 이름 | **easime** (Easy Eastern Asian IME) 확정 | — |
| 라이선스 | **MIT OR Apache-2.0** | 완료 |
| 저장소 | GitHub 공개 `byeonggonlee/easime`, 기본 브랜치 `main` | — |
| 대상 앱 | 브라우저, 터미널/KDE 앱, Electron/IDE, 게임/Wine/Steam — **가능한 한 전부** | 일부: Wayland 네이티브만. XWayland(XIM)는 예정 |
| 입력 상태 범위 | **전체 공통** (모든 창이 하나의 상태 공유). 창별 기억은 나중 옵션 | Linux 완료. Windows는 DLL이 앱마다 들어가 모드가 앱마다 따로(공유는 예정) |
| 언어 전환 | **순환**: 한 키로 영어 → 한국어 → 일본어 → 중국어 → … (설정에서 켠 언어만, 순서 변경 가능). **Windows도 같다**(2026-11-08 사용자 결정으로 "언어별 프로필"을 뒤집음, 아래 "Windows 등록 방식") | 완료 |
| 한/영 전환 키 | **한/영 키**, **오른쪽 Alt**(단독 탭), **둘 다** 중 GUI에서 선택. **기본은 둘 다**(2026-11-08 사용자 결정: 미국식 키보드에는 한/영 키가 없으므로 설치하자마자 전환이 되어야 한다. 이전 문서의 "기본: 한/영 키"는 실제 동작과 어긋나 있던 것을 바로잡은 것). 오른쪽 Alt를 다른 용도로 쓰는 사용자는 설정에서 "한/영 키"만 고른다. Windows에서는 오른쪽 Alt 누름을 응용 프로그램에 그대로 보내고 탭의 뗌에서만 전환한다(TSF 한계, [platforms.md](platforms.md)) | 완료 |
| 언어 선택 | **어떤 언어도 필수가 아니다.** 한국어만, 일본어만, 둘 다 쓰는 구성이 모두 가능하고 설정 UI에서 쉽게 고른다. **기본값 (2026-11-07 사용자 결정): 영어 + 시스템 언어.** 설정 파일에 `languages.enabled`가 없으면 시스템 언어(`LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`)와 맞는 입력 언어만 켠다: 한국어 시스템이면 한국어, 일본어 시스템이면 일본어. 동아시아 언어가 아니거나 아직 엔진이 없는 언어(중국어)이면 **모두 끄고 영어만** 쓴다. 사용자가 한 번 바꾸면 그 목록이 저장되어 이후에는 시스템 언어와 상관없고, `enabled = []`도 "모두 끔"이라는 선택이다. 이미 `enabled`가 있는 사용자의 설정은 바뀌지 않는다 | 완료 |
| 한국어 자판 | **두벌식만**. 엔진은 세벌식을 나중에 붙일 수 있게 설계 | 완료 |
| 백스페이스 | **자모 단위** 기본 (`한` → `하` → `ㅎ`), 설정에서 글자 단위로 변경 가능 | 완료 |
| 한자 변환(한국어) | 조합 중 **한 글자** 변환을 사용자 요청으로 추가(2026-11-07). 한자 키 → 후보 선택 → Enter 확정 / Esc 복귀. 단어·선택 영역·확정한 글자의 재변환은 후속 | 완료. 실제 KDE 재검증 필요 |
| 일본어 | **로마자 입력**. 1단계 가나만 → 2단계 한자 변환(Mozc 데이터 참고). 변환은 단어 단위이며 문절·문맥 변환은 별도 단계 | 완료(단어 단위) |
| 학습/사용자 사전 | **일본어 한자 변환 단계에서** 추가, 로컬에만 저장 | 예정 |
| 중국어 | **병음 입력**. 간체와 번체는 **별개의 입력 언어**(`简体中文`, `繁體中文`)로 두고 순환과 설정 목록에 따로 나온다 (2026-11-07 사용자 결정: Windows·macOS의 중국어 키보드가 간체/번체를 따로 두는 일반적인 구조를 따른다). 설정 파일 이름은 `chinese_simplified`, `chinese_traditional`. 상태 표시 글자는 엔진을 만들 때 정한다(지금은 둘 다 `中`) | 설정·로케일 완료. 엔진은 예정 |
| 상태 표시 | **트레이 아이콘** + **커서 아래 사각 박스**(`한`/`A`/`あ`/`中`): 사용자가 언어를 전환할 때만 약 1초 표시. 입력창 포커스 진입·복귀에는 표시하지 않음 (2026-11-07 사용자 피드백 반영) | Linux 완료(트레이·박스). Windows는 박스만, 상시 표시(알림 영역·언어 바)는 예정 |

### 플랫폼·배포

| 항목 | 결정 | 구현 |
|---|---|---|
| 플랫폼 순서 | **Linux(KDE → GNOME) → Windows → macOS** | KDE·Windows 완료(Windows는 실제 PC 미시험). GNOME·macOS 예정 |
| Linux 데스크톱 | **KDE Plasma 6** 최우선, 그다음 **GNOME** | KDE 완료 |
| Linux 패키지 | **GitHub Releases에 .deb / .rpm** (GitHub Actions로 빌드). 배포판당 패키지 하나(데몬 + 설정 창 + 사전, 2026-11-07 사용자 요청) | 패키지 완료. 릴리스는 태그 푸시 때(아래 "릴리스") |
| 설치 후 활성화 | **설정 창에 활성화 화면** (2026-11-08 사용자 결정): 패키지를 설치해도 easime가 입력기로 선택되지는 않으므로(설치 스크립트가 데스크톱 설정을 몰래 바꾸지 않는다), 설정 창이 "아직 입력기로 선택되지 않았습니다"를 알리고, 사용자가 누르면 바꿀 설정을 보여 주고 확인을 받은 뒤 적용한다. 되돌리기를 같은 화면에 둔다. KDE Plasma(Wayland)에서 `kwinrc`의 `[Wayland] InputMethod`를 쓰고, 다시 로그인해야 적용된다 | 완료 |
| 릴리스 | **v0.1.0 전에는 `main`에 직접 커밋·푸시**하고 브랜치·PR·태그를 만들지 않는다. **태그와 릴리스는 사용자가 정한다.** 첫 릴리스는 실제로 검증한 환경과 언어·앱 범위를 명시한 제한된 릴리스를 권장한다([평가](records/2026-11-08-assessment.md), 권장안이며 결정이 아니다). Windows 설치 파일은 실제 PC에서 시험하기 전에는 릴리스에 올리지 않는다 | 적용 중 |

### Windows

| 항목 | 결정 | 구현 |
|---|---|---|
| Windows 등록 방식 | **프로필 하나** (2026-11-08 사용자 결정, 같은 날 앞선 "언어별 프로필" 결정을 뒤집음): easime 프로필을 **하나**만 등록하고(이름 `easime`, **한국어 아래**), 그 안에서 Linux와 같은 순환(영어 → 켠 언어들 → 영어, 설정의 언어 목록과 순서)을 한 키로 돈다. 이유: 한 키로 영→한→일→영을 돌고, 설치할 때 Windows 언어를 여러 개 추가하지 않아도 된다. 대가: 작업 표시줄의 언어 표시는 일본어를 쳐도 한국어로 남고(어느 언어인지는 커서 옆 상자가 알린다), 응용 프로그램이 입력 언어로 하는 일(맞춤법 언어 등)이 일본어 입력과 어긋날 수 있는지는 확인하지 않았다. 타자가 되는 언어만 순환에 넣고(`frontend-tsf::profiles::TYPEABLE`: 한국어, 일본어), 사용자가 고른 언어가 아직 타자 불가라 순환이 비면 한국어, 하나도 고르지 않았으면(`enabled = []`) 영어만 쓴다. **모든 언어 아래 등록은 시험해 적용했다가 되돌렸다**(2026-11-08, "이상하면 한국어 아래로 되돌린다"는 조건대로): 켜자마자 사용자가 고르지 않은 프로그램들에서도 서비스가 켜졌고 제거 때 Windows Installer가 그 프로그램들을 닫아 CI 러너까지 멈췄다([경위와 실험 결과](records/2026-11-08-windows-plan.md)). 사용자 언어 아래에서 찾게 하는 다른 방법(같은 easime를 언어마다 등록하고 설치한 사용자의 첫 언어 아래에서만 켜기 등)은 **실제 PC 시험(W1–W18) 뒤에 다시 정한다**(2026-11-08 사용자 결정). 그때까지는 한국어 아래 하나다 | 완료 |
| Windows 설치와 언어 켜기 | **설치 파일이 설치한 사용자의 입력 방법에 easime를 켠다** (2026-11-08 사용자 요청: 키보드만 치려는 사용자가 많으므로 Windows 설정에서 직접 추가하게 하지 않는다). 한국어 아래에 켜고, 한국어가 사용자 언어 목록에 없으면 Windows가 더한다. 설치 창에서 기능을 고르게 해 그 화면이 확인이고(무인 설치는 켬), 제거가 되돌리기다. 다른 사용자의 설정은 건드리지 않는다(등록은 기계 전체, 켜기는 설치한 사용자만) | 완료 |
| 사용 중 제거·업그레이드 | **다른 프로그램을 닫지 않는다** (2026-11-08 사용자 결정): easime를 쓰는 동안 DLL은 그 프로그램들 안에 있다. 설치 프로그램은 그 프로그램들을 닫지 않고(무인 설치에서도), 사용 중인 파일은 다음 재시작 때 바꾸며, 재시작이 필요하다고 알린다. 이유: 저장하지 않은 글을 잃지 않는다(텍스트 보존). Windows Installer의 기본 동작(설치 창에서는 닫을지 묻고, 무인 설치에서는 닫는다)을 쓰지 않는다 | 완료 |
| Windows 일본어 지원 방식 | 일본어를 순환에 넣을 때 함께 한다(2026-11-08, [Windows 계획](records/2026-11-08-windows-plan.md)에서 사용자와 합의한 추천안): 사전 파일은 읽기 전용 **메모리 매핑**으로 **첫 변환 때** 열어 프로세스들이 나눠 쓴다. 조합은 **밑줄**로 보인다(한국어 실선, 일본어 읽기 점선, 변환 중인 부분 굵은 실선, 색은 응용 프로그램의 것). 후보를 직접 그리는 응용 프로그램에는 TSF **UI 요소**로 목록을 넘긴다. **스토어 앱** 범주를 등록하되 설정을 못 읽으면 기본값으로 동작한다. 로그인 화면·UAC용 `SECUREMODE`는 보안상 등록하지 않는다 | 완료 |
| Windows 설치 파일 형태 | **`setup.exe`(번들) 안에 MSI**: Windows App Runtime(설정 앱이 필요로 하는 Microsoft 프레임워크 패키지)이 없을 때만 Microsoft의 공식 설치 파일을 받아 실행하고 easime MSI를 설치한다(2026-11-09 사용자 결정, 전날의 "설치 파일에 포함"을 뒤집음). 이유: Microsoft Windows App SDK 라이선스(3.b)는 재배포를 허용하지만 배포자에게 최종 사용자가 Microsoft를 보호하는 조건에 동의하게 할 의무와 Microsoft를 면책할 의무를 지운다(법률 검토는 아님). **easime 파일에는 Microsoft 바이너리가 없다.** 대가: 설치할 때 인터넷이 필요하고(116MB), 설치 파일이 MSI 하나에서 번들로 바뀐다. 런타임 없이 설정 앱을 열면 Microsoft의 설치 안내가 뜬다 | 완료 |

### 설정 앱

| 항목 | 결정 | 구현 |
|---|---|---|
| 설정 GUI | **OS별 네이티브**: Linux = Kirigami, Windows = WinUI 3, macOS = SwiftUI. Windows의 WinUI 3는 2026-11-08 사용자가 다시 확인했다(컨셉에 맞는 미려함과 OS 일체감). **Windows 설정 앱은 Rust + `windows-reactor`**(Microsoft가 windows-rs에 넣은 Rust용 WinUI 3 라이브러리, 2026-11-08 사용자 결정): 나머지 코드와 같은 언어라 Linux 설정 앱의 저장 규칙(바뀐 키만 고치고 주석·순서 보존, 못 읽는 파일은 덮어쓰지 않음)을 그대로 쓴다. 대가: 새 라이브러리라 API가 바뀔 수 있고 예제가 적다. 런타임 배포 방식은 위 "Windows 설치 파일 형태" | Linux·Windows 완료. macOS 예정 |
| 설정 UI 단계 | 목표는 **초보자용과 전문가용을 나누는 것**. 단기에는 **전문가용만** 만든다: 모든 옵션을 바로 보여 주는 일반 설정 창이며, 변경은 바로 설정 파일에 저장되고 데몬이 다시 읽는다. 초보자용(첫 실행 안내, 쉬운 설정, 복구 안내)은 그다음 단계 (2026-11-07 사용자 결정) | 전문가용 완료. 초보자용 예정 |
| 설정 창 표시 언어 | **한국어, 日本語, 繁體中文, 简体中文, English** 다섯 가지 (2026-11-07 사용자 결정, 입력 언어 목록과는 별개). 시스템 언어를 따르고 그 밖의 언어는 영어로 보인다. 한국어 외의 번역은 **원어민 검토 전 초안**이며, 번역된 화면은 그 사실을 알린다 | 완료(번역 검토 예정) |

### 보조 도구 (클립보드·이모지)

핵심 입력과 복구 흐름의 검증이 먼저이고, 보조 도구는 선택적으로 켠다([DESIGN.md](../DESIGN.md) 3.6, 5.4). 모두 **예정**이다.

| 항목 | 결정 | 구현 |
|---|---|---|
| 단축키 충돌 | **easime가 대체**: 설정 앱/첫 실행 안내에서 Klipper(`Meta+V`)와 이모지 선택기(`Meta+.`)의 전역 단축키를 해제하고 easime가 쓰도록 한 번에 설정. **되돌리기 버튼 필수**. 사용자 설정을 바꾸는 일이므로 항상 사용자 확인 후 실행 | 예정 |
| 클립보드 | **텍스트 기록**만 (`ext_data_control_v1`로 감시, 입력기 `commit_string`으로 붙여넣기). **비밀번호 관리자 항목은 제외**(`x-kde-passwordManagerHint` 등). 기본은 메모리에만 보관, 디스크 저장/이미지 기록은 하지 않음 | 예정 |
| 이모지/카오모지 | **Unicode CLDR 이모지**(한국어/일본어/중국어 이름·검색어 포함) + **라이선스 확인된 카오모지 번들**. 최근 사용/즐겨찾기 지원 | 예정 |
| 팝업 UI | **입력 패널 + 직접 렌더**(후보창과 같은 방식, 키 입력은 입력기가 처리해 검색어 입력 가능). 시스템 색상 연동은 직접 구현. 완성도를 보고 Kirigami 전환 여부는 나중에 재검토 | 예정 |

## 라이선스 메모
- Mozc는 코드가 **BSD-3-Clause**이고, OSS 사전 데이터도 허용적 라이선스(IPAdic 계열 등)이다.
  따라서 MIT/Apache-2.0 프로젝트에서 참고하거나 포함할 수 있다. 저작권 고지만 유지하면 된다.
- Qt/Kirigami(LGPL)는 동적 링크이므로 문제없다.
- Microsoft Windows App Runtime은 재배포하지 않는다(위 "Windows 설치 파일 형태").
- 제3자 데이터는 `data/<출처>/`에 원본 LICENSE를 함께 두고 `THIRD_PARTY_LICENSES.md`에 기록한다.
- 중국어 사전 후보 중 GPL/CC BY-SA 데이터(예: libpinyin, CC-CEDICT)는 본체와 섞지 말고
  **별도 데이터 패키지**로 분리하거나, 허용적 라이선스 데이터를 우선 검토한다.
