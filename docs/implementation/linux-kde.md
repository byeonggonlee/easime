# Linux (KDE Plasma 6) 구현 현황

기준: 2026-11-10, `main` 381e664. 한눈에 보는 현황은 [status.md](../status.md), 실제 KDE에서 시험하는 절차와 기록은 [KDE 시험 절차서](../testing/kde.md)다.

**사람이 실제 KDE에서 써 본 것은 한·영 입력뿐이다**(2026-11-07, Fedora 최신, 커밋 `107bb4b`). 한자·일본어 변환, 트레이, 설정 창, 활성화 카드, 패키지 설치는 가짜 KWin 테스트와 컨테이너 CI로만 확인했다. 앱별 범위도 확인하지 않았다.

## 입력기 데몬

- KWin이 가상 키보드로 실행하는 프로세스 하나가 모든 창을 맡는다(전체 공통 입력 상태, 일본어 사전도 한 번만 연다). 일반 클라이언트에는 `zwp_input_method_v1`이 노출되지 않아(KWin 6.8.2 확인: 입력기로 등록된 프로세스에만 제공) 가상 키보드로 등록해야 시험할 수 있다.
- 키를 grab하므로 키 반복은 직접 한다(자체 타이머와 컴포지터 `repeated`). Caps Lock은 무시한다. 한글 자판은 활성 키보드 레이아웃의 keysym을 따른다(물리 키 위치 기준 아님): 레이아웃이 US가 아니면 어긋날 수 있다.
- 후보창과 상태 박스는 입력 패널(`zwp_input_panel_surface_v1`) 하나를 번갈아 쓴다. 후보창 폭은 내용에 맞춰 400~960px로 늘고, 더 길면 `…`로 끝난다. 후보를 띄울 수 없으면 변환을 시작하지 않고 읽기를 유지한다.
- 변환 중에는 프리에딧에 선택한 후보가 보이고 Enter로 확정한다(앱에는 전달하지 않음). 한영 전환과 포커스 이탈은 보이는 후보를 한 번 확정한다.
- 설정 파일이 심볼릭 링크이면(도트파일 관리자) 설정 창은 링크를 지킨 채 가리키는 파일에 저장하고, 데몬은 링크가 가리키는 폴더도 그 파일 이름만 감시한다(2026-11-08 수정).

## 언어 전환

한/영 키 또는 오른쪽 Alt 탭은 기본적으로 영어와 마지막 언어 사이를 오가고, Shift를 누른 채면 순환의 다음 언어로 간다([공통 코어](core.md)). 키가 어느 키인지는 수정 키와 상관없이 첫 레벨의 키심으로 판정한다(일반 키맵에서 오른쪽 Alt는 Shift를 누르면 `Meta_R`이 되기 때문이다). 트레이 아이콘 클릭은 전환 키와 같은 동작이고 메뉴는 언어를 직접 고른다. 설정 창의 단축키 화면에서 "언어 전환 방식"을 고른다(Fedora CI가 클릭해서 설정 파일에 `switch = "cycle"`이 써지는 것을 확인한다). 실제 KDE에서는 써 보지 않았다.

## 상태 박스와 트레이

- **상태 박스**(`indicator`, `font`, `panel`): 사용자가 언어를 전환할 때만 `A`/`한`/`あ`/`中` 48×48 박스를 `indicator_ms`(기본 1000) 동안 보이고, 그 전에 전환 키·보조 키가 아닌 키가 눌리면 바로 숨긴다(2026-11-10 사용자 요청, Windows 회사 PC 피드백). KWin이 커서 사각형 바로 아래에 배치하고 키보드 포커스를 갖지 않으며 입력 영역이 비어 있다. `[appearance] indicator_box`로 끈다. 포커스만으로는 뜨지 않는다(2026-11-07 사용자 결정). text-input-v1 앱은 커서 위치를 보내지 않아 창 왼쪽 위에 뜰 수 있다.
- **트레이 아이콘**(2026-11-07 사용자 요청, `crates/easime/src/tray.rs`): 현재 언어를 둥근 배지 안의 글자로 보이고(16·22·24·32·48·64px), 툴팁은 언어 이름이다. 2026-11-08 실기 피드백으로 글자 잉크가 배지 폭·높이의 약 76%를 채우도록 키우고 굵은 글꼴·순백색을 썼다(`indicator::render_tray`). 클릭하면 다음 언어로 바뀌고, 우클릭 메뉴에는 켠 언어(라디오)와 "easime 설정"이 있다. 전환 요청은 다른 스레드의 채널로 입력 스레드에 가서 조합 중인 글자를 확정한 뒤 처리되고, D-Bus는 별도 스레드가 맡아 입력이 느려지지 않는다. 고정 다크 배지라 시스템 색을 따르지 않는다. 메뉴 항목의 동작은 단위 시험까지만 했다(D-Bus로 눌러 보지는 않았다).
- **앱 아이콘**(`data/icons/`, `scripts/generate-icons.py`): 다국어 키캡(`한` 중심, `A`·`あ` 배지, 순환 궤도) 512×512 기본과 파생 크기(PNG, SVG, Windows `.ico`)를 만들어 `.desktop`과 패키지에 넣었다. 32px에서는 작은 보조 글자 구별이 제한적이다.

## 설정 창 (`settings/kde`)

Rust + cxx-qt + QML + Kirigami. 메인 워크스페이스와 별개의 cargo 프로젝트다(Qt 6가 필요). 모델·저장 규칙은 `easime-settings-model`을 쓴다.

- **페이지**: 일반(활성화 카드, 지원·사전 상태, 파일 위치·다시 읽기·초기화), 언어(켜기/끄기, 전환 순서, 순서 미리보기), 단축키(전환 키), 한국어(백스페이스 단위), 모양(상태 박스, 표시 시간을 초 단위로). 어떤 언어도 필수가 아니다. 简体中文과 繁體中文은 따로 "준비 중"으로 나온다.
- **저장**: 변경은 바로 저장되고 데몬이 다시 읽는다. 바뀐 키만 `toml_edit`으로 고치므로 직접 쓴 주석과 모르는 키가 남고, 읽을 수 없는 파일은 덮어쓰지 않으며(변경을 거부하고 알림), 초기화는 `config.toml.bak`을 남긴다.
- **입력기 활성화**(2026-11-08 사용자 결정): 일반 페이지 맨 위 카드가 `kwinrc`의 `[Wayland] InputMethod`로 easime가 선택되었는지 알려 준다. [입력기로 사용하기…]는 바꿀 파일과 지금 값을 보여 주고 확인을 받은 뒤 적용하며(다시 로그인하면 적용), 이전 값을 `~/.config/easime/activation-backup.toml`에 두어 [이전 입력기로 되돌리기…]가 정확히 그 값을 되돌린다. 그 사이 사용자가 다른 입력기를 골랐으면 건드리지 않는다. `kwinrc`의 다른 줄과 주석은 그대로 둔다. KDE가 아니면 카드가 보이지 않는다. "실행 중" 문장은 검출한 것(선택됨, 실행 중)만 말하고 실제 입력이 되는지는 알 수 없다.
- **일반 화면의 준비 상태**(2026-11-08 평가 반영): 일본어를 켰을 때 사전 상태("있음(파일 n개)", "찾지 못함", "읽지 못한 파일 n개")를 보이고, 모든 입력 언어가 꺼져 있으면 "지금은 영어로만 입력됩니다"와 언어 화면으로 가는 버튼을 맨 위에 둔다.
- **표시 언어**: 한국어, English, 日本語, 繁體中文, 简体中文. 시스템 언어(`LANGUAGE`/`LANG`)를 따르고 그 밖은 영어이며 `--ui-language=ko|en|ja|zh-Hant|zh-Hans`로 지정할 수 있다. 문구는 한국어 원문을 키로 한 표 하나(`qml/tr.js`, Windows 설정 앱도 사용)에 있다. **한국어 외의 번역은 원어민 검토 전 초안**이고 번역된 화면의 일반 페이지가 그렇게 알린다. 자동 검사는 누락·미사용·빈 번역·`%1` 불일치와 언어 선택만 확인하며, 번역의 정확성·자연스러움과 한자의 언어별 자형은 확인하지 않았다.
- **CI**(`settings` 잡, Fedora 컨테이너): 실제 Kirigami로 빌드하고 오프스크린으로 5개 페이지를 모두 열어 QML 경고를 실패로 취급하며, 컨트롤을 `click()`으로 눌러 설정 파일이 바뀌는 것까지 확인한다. 다섯 표시 언어로 각각 열고, 시스템 언어별 기본 입력 언어(ko → 한국어, ja → 일본어, 그 밖 → 없음)도 확인한다. 화면 캡처는 아티팩트 `settings-window-pages`에 남는다. 색·간격·사이드바의 보이는 모습, 키보드 탐색·스크린 리더·큰 글씨·혼합 배율은 확인하지 못했다.
- 아직 없음: 자동 실행, 초보자용(첫 실행 안내), 번역의 원어민 검토, 설정 창 안에서 표시 언어를 고르는 선택지, 일본어·중국어 페이지(옵션이 생길 때 추가).

## 패키지

- **배포판당 패키지 하나**(`easime`: 데몬, 설정 창, `easime.desktop`, `easime-settings.desktop`, 아이콘, 일본어 사전)를 `.deb`/`.rpm`으로 만든다(2026-11-07 사용자 요청: 키보드와 설정을 따로 설치하게 하지 않는다). Qt 6·Kirigami가 있는 컨테이너에서 만든다: `.rpm`은 Fedora, `.deb`는 Debian 13. 그러므로 `.deb`는 Debian 13 이상, Ubuntu는 Plasma 6와 Qt가 충분히 새로운 25.04 이상을 대상으로 하며, 시험한 것은 clean `debian:trixie`와 `fedora:latest`뿐이다.
- 빌드와 검증은 `.github/workflows/packages.yml` 하나다. CI와 릴리스(`release.yml`)가 같은 흐름과 같은 실제 Mozc 사전을 쓴다. 각 패키지를 clean 컨테이너에 설치해 데몬이 시작되어 이유를 말하며 멈추는지(컴포지터가 없으므로)와 설정 창이 모든 페이지를 여는지 확인한 뒤 두 파일이 한 아티팩트(`easime-linux-packages-<commit>`)로 묶인다.
- 태그 `v*`를 푸시하면 릴리스 워크플로가 GitHub Releases에 올리지만, 태그와 두 크레이트(`easime`, `easime-settings`)의 버전이 같아야 진행된다. **태그는 사용자 결정이며 v0.1.0 전에는 푸시하지 않는다.**
- 설치해도 easime는 입력기로 자동 선택되지 않는다(설치 스크립트가 데스크톱 설정을 몰래 바꾸지 않는다): 설정 창의 활성화 카드나 시스템 설정 → 키보드 → 가상 키보드에서 고르고 다시 로그인한다.
- 데몬이 Qt에 의존하므로 KDE가 아닌 데스크톱(GNOME 등)에 설치하면 Qt가 함께 설치된다. GNOME 지원이 생기면 다시 나눌지 따진다.

## 실사용 보고와 알려진 한계

- 2026-11-07 Fedora 최신 + `107bb4b`: 한·영 입력이 동작한다. 상태 박스가 나타날 때 하단 태스크바 전체가 움직였으나 KWin 6.8.1의 오버레이 표시 상태 오분류(bug 527067)와 일치했고, easime 재설치 없이 재부팅해 KWin 6.8.2를 적용하자 재현되지 않았다. 경위와 재현 절차는 [KDE 시험 절차서](../testing/kde.md). 포커스 시 박스 표시를 없앤 로컬 수정본과 한자 기능은 설치 후 검증이 남아 있다.
- 상태 박스와 후보창은 고정 다크 테마다. Plasma 색상 연동은 없다. 후보창은 시스템 글꼴 크기·혼합 배율도 따르지 않는다(입력 패널 scale 1).
- 한도를 넘는 긴 후보의 전체 내용을 현재 선택에서 확인하는 방법은 없다(말줄임만).
- 가짜 KWin 하네스(`crates/frontend-wayland/tests/`)는 실제 KWin 없이 프로토콜 흐름을 시험하며 실제 버그(`KeyState::Repeated` 처리)를 잡은 적이 있다. 실제 KWin의 동작을 대신하지는 않는다.
