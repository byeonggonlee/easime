# Windows 실사용 확인 절차

이 문서는 **절차서이자 기록 양식**이다. CI는 실제 Windows의 TSF와 Windows Installer 위에 가짜 응용 프로그램(창과 문서)을 세워 한글·일본어 타자, 설치·업그레이드·제거, 설정 앱 열기를 확인할 뿐이며, 메모장·브라우저·메신저·게임 같은 실제 응용 프로그램과 실제 PC의 결과는 아래 표에 적힌 것뿐이다. 2026-11-09에 W1–W14가 문제 없이 통과했다고 보고되었다(상세는 표). 2026-11-10에는 회사 PC에 설치해 쓰며 W19의 결과(단추는 보이지만 작고, 단추와 Windows 설정 화면으로는 easime 설정에 들어갈 수 없음)와 두 가지 긍정·개선 의견이 보고되어 고쳤고, 그 재확인이 W19·W21이다. W15·W17은 시험하지 않았다. 구현 범위와 한계는 [Windows 구현 현황](../implementation/windows.md), 전체 현황은 [status.md](../status.md)를 따른다.

**이 시험의 결과로 정할 것**: Windows 설정에서 easime를 어느 언어 아래에 보일지([decisions.md](../decisions.md) "Windows 등록 방식")는 실제 PC 시험 뒤에 다시 정하기로 했다. 그래서 설치 후 **설정 → 시간 및 언어 → 언어 및 지역에서 easime가 어디에 어떻게 보이는지**, **작업 표시줄의 언어 표시가 무엇인지**(한국어로 남는지), W12(스토어 앱)의 결과를 꼭 적는다.

## 설치

1. CI 실행의 아티팩트 `easime-windows-installer-<commit>`을 받아 압축을 풀고 `easime-setup-<버전>-x64.exe`를 실행한다(MSI만 설치하려면 `easime-<버전>-x64.msi`). 코드 서명이 없어 SmartScreen 경고가 뜰 수 있다. Windows App Runtime이 없는 PC에서는 `setup.exe`가 Microsoft에서 설치 파일(약 116MB)을 받아 먼저 설치하므로 인터넷이 필요하다(W17).
2. 설치 창에서 "easime keyboard"가 켜져 있는지 본다. 설치가 끝나면 설정 → 시간 및 언어 → 언어 및 지역에 한국어와 키보드 `easime`가 있어야 한다(프로필은 하나이고 한국어 아래에 있다). 없으면 그 사실과 `%LOCALAPPDATA%\easime\easime.log`를 기록한다. 시작 메뉴에 "easime"(설정 앱)가 있어야 한다.
3. 작업 표시줄의 언어 표시 또는 Win+Space로 `easime`를 고른다.

## 입력 시험 (앱마다 한 번씩)

앱 후보: 메모장, 브라우저(Edge 또는 Chrome)의 입력창, 메신저, 워드패드 같은 서식 있는 편집기. 32비트 프로그램에서도 되어야 하므로(32비트 DLL을 함께 설치한다) 안 되면 실패로 적는다(W23). 시험 중에 키를 잃는 경우를 찾으려면 환경 변수 `EASIME_LOG_KEYS=1`로 앱을 다시 시작해 `easime.log`에 모든 키가 남게 한다.

## 제거

설정 → 앱에서 easime를 지운다(또는 `msiexec /x`). 한국어 언어와 `easime` 키보드가 목록에서 사라지고, 다른 언어 설정은 그대로여야 한다. 설치 프로그램은 easime를 쓰던 프로그램을 **닫지 않는다**(2026-11-08 결정). 바로 바꾸거나 지울 수 없는 파일은 다음 재시작 때 처리되고, 그때는 재시작이 필요하다고 알린다. 사용 중인 프로그램을 둔 시험은 W18이다. CI에서는 DLL을 불러 둔 프로그램을 띄운 채 무인 업그레이드·제거를 했고, 그 프로그램은 살아 있었으며 재시작 요청 없이 끝났다(쓰던 DLL은 `C:\Config.Msi`로 옮겨져 다음 재시작 때 지워진다). 제거하면 설정 앱과 시작 메뉴 항목도 사라지고, Windows App Runtime은 남는다.
