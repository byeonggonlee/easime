# KDE 실사용 확인과 하단 패널 문제

## 확인한 범위

2026-11-07 사용자가 Fedora 최신 환경에서 커밋 107bb4bbcc24bfc83b063cfd69c4a052b44fb616을 시험했다.
한·영 입력은 동작했고, 언어 상태 박스가 나타날 때 하단 태스크바 전체가 위아래로 이동하거나 크기가 바뀌었다고 보고했다.
재부팅 전 사용자는 kwin-wayland --version 결과가 6.8.2라고 보고했고, DBus 관찰에서 박스 등장 때 visible=b true, 퇴장 때 b false로 바뀐다고 확인했다.
이후 easime를 재설치하지 않고 재부팅해 KWin 6.8.2를 적용하자 하단 패널 문제가 재현되지 않는다고 확인했다.
이 사용자 환경에서는 KWin 업데이트 적용으로 문제가 해소된 것으로 기록한다. 재부팅 후 DBus 속성은 재측정하지 않았다.
앱별 검증 범위는 미확인이며, 이를 모든 앱에서의 동작 보장으로 확대하지 않는다.

## 포커스 진입 때의 불필요한 표시

사용자는 입력창 포커스가 잡힐 때 박스를 띄우는 것도 문제라고 추가 보고했다.
이에 activate 경로의 자동 표시를 제거해, 입력창 클릭·재진입만으로는 언어 박스를 띄우지 않는다.
명시적 언어 전환 때의 표시와 한자 키로 여는 후보창은 유지한다.
이 변경은 표시를 유발하는 동작 하나를 제거한 것이며, 언어 전환 때의 태스크바 이동까지 해결했다는 뜻은 아니다.
사용자의 기존 설치본에는 재부팅 뒤에도 포커스 시 표시가 남아 있다. 로컬 수정본 설치 후의 포커스 동작은 아직 확인하지 않았다.

## 증상 영상에서 확인한 동작

사용자가 제공한 `20261107_140135.mp4`(약 16.7초)의 표시 전·중·후 프레임을 확인했다.
약 6.2초의 A 박스와 약 9.4초의 한 박스가 나타나면 하단 패널 아래의 배경 여백이 사라지고,
박스가 사라지면 여백이 돌아온다. 아이콘 추가로 인한 재배열보다 패널의 floating 상태 전환에 해당하는 모습이다.
카메라로 모니터를 촬영한 영상이므로 정확한 이동량이나 창 geometry는 이 영상만으로 측정하지 않는다.
이 관찰과 사용자가 별도로 확인한 DBus visible=true/false 변화가 같은 원인 경로를 뒷받침한다.

영상의 터미널에는 패키지 업데이트 완료 출력과 kwin / kwin_wayland --version의 6.8.2 결과가 보인다.
촬영 당시 실행 중이던 KWin의 정확한 버전은 영상만으로 판단할 수 없었다. 이후 재부팅하여 6.8.2를 적용한 뒤 증상이 사라졌다는 사용자 확인을 받았다.
원본 영상이나 사용자 환경이 드러나는 프레임은 저장소에 포함하지 않는다.

## 원인 경로와 재부팅 후 확인: KWin의 오버레이 표시 상태

easime는 커서 옆 상태 박스와 후보창을 Overlay로 요청한다. 하단 가상 키보드 역할은 요청하지 않는다.
사용자가 시험한 커밋과 현재 작업본의 상태 박스 역할 지정은 같다.

[KWin 6.8.1의 isVisible](https://github.com/KDE/kwin/blob/v6.8.1/src/inputmethod.cpp#L896)은
Overlay도 가상 키보드가 표시 중인 것으로 보고한다.
[Plasma 하단 패널](https://github.com/KDE/plasma-desktop/blob/Plasma/6.8/desktoppackage/contents/views/Panel.qml#L81)은
이 값으로 floating 상태를 바꾸므로, 상태 박스 등장·퇴장 때 패널 전체가 움직일 수 있다.
[KWin 6.8.2](https://github.com/KDE/kwin/blob/v6.8.2/src/inputmethod.cpp#L897)는 Overlay를 제외하도록 수정됐다.
[공식 변경 기록](https://kde.org/announcements/changelogs/plasma/6/6.8.1-6.8.2/)의 bug 527067에 해당한다.

재부팅 전에는 실행 파일 버전만 6.8.2로 확인됐으며, 박스의 표시·숨김이 DBus 가상 키보드 visible 상태로 전달됐다.
Plasma 하단 패널의 floating 상태가 이 값에 반응하는 소스 경로와 영상의 증상이 일치했다.
이후 동일한 easime 설치본으로 재부팅해 KWin 6.8.2를 적용하자 문제가 재현되지 않았다는 사용자 확인을 받았다.
따라서 이번 보고는 KWin 업데이트가 실행 중 세션에 적용되기 전의 문제로 정리하며, easime의 패널 역할이나 크기를 바꾸는 우회 수정은 추가하지 않는다.
재부팅 전 프로세스의 정확한 버전은 소급 확인하지 못했고, 재부팅 후 visible 값이 false를 유지하는지는 별도 측정하지 않았다.

## 같은 증상이 다시 발생할 때의 읽기 전용 확인

Fedora KDE 터미널에서 다음을 실행한다. 스크립트는 설정이나 입력기 등록을 바꾸지 않고,
설치 패키지·실행 중 KWin 버전과 가상 키보드 표시 속성만 읽는다. 입력한 문장과 키 입력은 수집하지 않는다.

    bash scripts/diagnose-kde-panel.sh --watch

12초 동안 텍스트 입력창에서 한/영 전환을 반복한다.
박스가 뜰 때 b true, 사라질 때 b false가 반복되면 위 버그 경로와 일치한다.
정상적인 Overlay라면 b false를 유지해야 한다.

패키지 버전과 실행 중 버전은 다를 수 있다. 구버전 KWin이 실행 중이라면 해당 수정을 포함한 배포판 업데이트와
로그아웃·재로그인 후 같은 확인을 권장한다. 에이전트는 이를 대신 실행하지 않는다.
업데이트 후 재로그인을 하지 않았다면 작업을 저장하고 한 번 로그아웃·로그인한 뒤 박스와 패널 동작을 다시 확인한다.
이후에도 박스에 맞춰 b true/false가 바뀌면 실행 중 버전과 배포 빌드를 기준으로 Overlay 오분류가 남은 원인을 조사한다.
6.8.2 이상의 실행 중 KWin에서도 b false를 유지하면서 패널이 움직이면,
패널의 floating 동작과 실제 geometry를 추가 조사한다. 버전 문자열만으로 수정 포함 여부를 단정하지 않는다.

## 증상이 남는 환경의 임시 우회

원인 확인 전 표시가 불편하면 사용자가 자신의 설정 파일에서 다음 값을 지정할 수 있다.
기존 appearance 절이 있으면 새 절을 중복 작성하지 않고 그 안의 값을 바꾼다.

    [appearance]
    indicator_box = false

이것은 커서 옆 언어 박스를 숨기는 우회이며 근본 수정이 아니다. true로 되돌리면 다시 표시한다.
한자 후보창은 별도로 표시하므로, 구버전 KWin의 같은 문제가 후보창에도 나타날 수 있다.

## 한자 입력 재검증

이 작업에서 추가한 첫 범위는 조합 중 한 글자 변환이다.
한국어 상태에서 한을 조합한 뒤 한자 키를 누르면 韓·漢 등의 후보가 나타나야 한다.
↑↓ 또는 Space로 이동하고, PgUp/PgDn으로 페이지를 바꾸며, Enter나 현재 페이지의 1–9로 확정한다.
Esc 또는 Backspace 한 번은 원래 한글 조합으로 돌아간다. 그 뒤 Backspace는 자모를 지운다.
창 이동·한영 전환은 확정하지 않은 한자 대신 원래 한글을 보존해야 한다.

별도 한자 키가 없는 키보드의 대체 단축키, 단어 변환, 이미 확정한 글자의 재변환은 이번 범위에 포함하지 않는다.
한국어 키보드 설정이 한자 키에 Hangul_Hanja 키심을 보내는지도 확인한다.
