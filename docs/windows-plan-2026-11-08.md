# Windows 다음 단계 계획 (2026-11-08)

사용자와 합의한 Windows 진행 순서와 추천안이다. 확정 결정은 [decisions.md](decisions.md), 구현·검증 상태는 [status.md](status.md)가 기준이다. 이 문서는 결정을 대신하지 않는다.

## 목표

- 하나의 easime 안에서 영어·한국어·일본어를 한 키로 순환한다(Linux와 같은 순환, 설정의 언어 목록과 순서).
- Windows 사용자가 어느 언어를 쓰든 easime를 찾아 켤 수 있다.
- 입력기, 사전, 설정 앱을 설치 프로그램 하나로 제공한다.

## 사용자 결정 (2026-11-08)

| 항목 | 결정 |
|---|---|
| 등록 방식 | **모든 언어 아래 등록을 시험한다.** "모든 언어"(`-1`)는 옛 API `ITfInputProcessorProfiles::AddLanguageProfile`에만 문서화되어 있고, easime가 쓰는 `ITfInputProcessorProfileMgr::RegisterProfile`에는 없다. 시험 결과가 나쁘면 지금처럼 한국어 아래 하나를 유지하고 한계를 안내한다. 바꾸기 전까지는 기존 결정(한국어 아래 하나)이다. |
| 설정 앱 | **WinUI 3**(기존 결정 재확인). 이유: 컨셉에 맞는 미려함과 OS와의 일체감. |
| 사전을 넣은 MSI | 실제 Mozc 사전과 원본 라이선스를 함께 설치하고, 설치 위치를 바꿔도 찾으며, 설정 앱에 사전 상태를 보인다. |
| 검증 | 작은 단위로 검사·커밋·푸시하고 CI를 확인한다. 실제 Windows 앱에서의 확인은 자동 검증과 구분해 기록한다. |

## 추천안: 일본어에 필요한데 처음 제안에 없던 것

| 항목 | 추천 |
|---|---|
| 사전 메모리 | Windows에서는 입력기 DLL이 응용 프로그램마다 들어간다. 사전 파일을 읽기 전용으로 **메모리 매핑**해 프로세스들이 같은 페이지를 나눠 쓰게 하고, **첫 변환 때** 연다. 지금은 파일 전체를 읽는다(`file_dict.rs`). Linux 데몬도 같은 코드를 쓴다. |
| 조합 밑줄 | Windows 일본어 입력기의 관례: 읽기는 점선, 변환 중인 후보는 굵은 실선, 한국어 조합 글자는 실선. 색은 지정하지 않아 앱 테마를 따른다(`ITfDisplayAttributeProvider`). |
| 전체 화면 앱의 후보창 | 후보창과 함께 UI 요소 방식(`ITfUIElementMgr::BeginUIElement`, `ITfCandidateListUIElement`)을 넣는다. 앱이 직접 그리겠다고 하면 우리 창 대신 목록을 넘긴다. |
| 스토어 앱 | 스토어 앱 지원 범주(`GUID_TFCAT_TIPCAP_IMMERSIVESUPPORT`)를 등록한다. 그런 앱에서 사용자 폴더의 설정을 읽지 못하면 기본값으로 조용히 동작한다. 로그인 화면·UAC용 `SECUREMODE`는 보안상 등록하지 않는다. |

## 진행 순서

각 단계는 커밋·푸시하고 CI를 확인한 뒤 다음으로 간다.

1. 이 계획과 결정 기록.
2. 등록 방식 실험: 일회용 클래스로 옛 API의 `-1`, 새 API의 `0xFFFF`, 일본어 하나를 등록해 Windows가 언어별로 무엇을 나열하고 사용자가 켤 수 있는지 CI 로그로 남긴다(`frontend-tsf/tests/languages.rs`). 결과로 적용 여부를 정한다.
3. 스토어 앱 범주와 설정을 못 읽을 때의 동작.
4. 사전: 메모리 매핑, 첫 변환 때 열기, DLL 위치 기준 경로, MSI에 사전과 라이선스.
5. 조합 밑줄(한국어부터).
6. 일본어 후보창(UI 요소 포함), 순환에 일본어 넣기(`profiles::TYPEABLE`).
7. WinUI 3 설정 앱(시작 메뉴, 일반·언어·단축키·한국어·일본어·모양; 일본어 페이지는 실제 옵션이 있을 때만, [DESIGN.md](../DESIGN.md) 5.5).

## 실제 PC에서만 확인할 수 있는 것

- Windows 설정의 언어 화면에 easime가 각 언어 아래 보이는지(2단계의 CI는 레지스트리와 TSF 목록까지만 본다).
- 스토어 앱(설정 앱의 검색창 등)에서 쓰이는지.
- 밑줄·후보창의 실제 모양, 전체 화면 앱, 혼합 배율.
- WinUI 3 설정 앱의 모양과 접근성.

절차와 기록 양식은 [windows-testing.md](windows-testing.md)에 더한다.

## 남는 대가

등록한 언어와 실제로 치는 언어가 다를 수 있다. 예를 들어 일본어 아래 켠 easime로 한국어를 치면, 응용 프로그램은 일본어 입력으로 본다(맞춤법, 글꼴). 등록 방식을 바꿔도 남는 문제이며 [decisions.md](decisions.md)의 "Windows 등록 방식"에 적혀 있다.
